# AGENTS.md: scripts

The checks and tools in `scripts/` that CI runs.

## Stack

- Benches: `criterion` 0.8 (Apache-2.0 OR MIT, default features off, `cargo_bench_support`), a dev-dependency of the root crate alone.

## Commands

- `python3 scripts/stories.py` writes `crates/ely-gallery/stories.json`, every page's sections in drawing order with their components, for the site: the names in a title, and in its `SHOWN` table what a story draws beyond them. It fails on a section opened inside another and on a ticked entry with a home of its own that no story names. `scripts/check.sh` refuses a stale one.
- `cargo test --workspace --exclude ely-gallery --lib --all-features`, `cargo test --workspace --exclude ely-gallery --doc --all-features`, `cargo test -p ely-gpui-component --all-features --test '*'` (the apps in `tests/`), `RUSTDOCFLAGS="--cfg docsrs -D warnings" cargo doc --workspace --exclude ely-gallery --no-deps` (the docs as docs.rs builds them), `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo fmt --all --check`, `python3 scripts/panics.py` (the panic list). `scripts/check.sh` runs them with the house rules and lints the gallery for wasm32. CI's `gate` job runs it on GitHub-hosted Linux, Windows and macOS, each counting its own panic sites, then builds the gallery, and on Windows walks the audit; no self-hosted runner gates a change.
- `python3 scripts/api.py [CRATE...]` (Linux) holds each library crate's public API, or the named ones', to its snapshot in `api/`, read by `cargo-public-api` on the nightly the script pins (`--toolchain` and `--tool` print the pins); `--write` takes new snapshots, and a change to the public API commits its snapshot with it. Snapshots read Linux's cfg and leave out `#[doc(hidden)]` items and blanket and auto-trait impls; each re-export names the item it reaches, a module reached through one is walked under its public path, and an item that not every feature set has (the defaults, none, each feature alone, all) names the sets that do. CI's `api` job runs it.
- `cargo publish --workspace --exclude ely-gallery --dry-run` packages and builds the 31 library crates in dependency order, each against its siblings as packaged. `python3 scripts/semver.py <base>` runs `cargo-semver-checks` (the version `--tool` prints) on every library crate one of whose packaged files (as `cargo package --list` names them, its folder when cargo cannot; a published crate reads no other, `#[path]` and `include!` too; a file deleted or moved away counts for the package whose folder held it), or a workspace dependency's, proc-macro crates included, changed since the base (a changed `Cargo.lock` or root manifest takes them all), against that crate's newest release on crates.io, with the default features, none where a crate declares a `default` feature, empty or not, and all, in one shared target directory (unset, the tool builds gpui again for each crate), and fails a breaking change since that release whose crate kept its version; several breaks inside one raised, unreleased version pass, since the raise marks them all. A crate with no release and an all-zero base, a branch's first push, have nothing to compare. CI's `semver` job runs it on the declared `rust-version` against the PR's base or the commit before the push.
- `cargo deny --workspace --all-features check` (cargo-deny 0.20; without `--workspace` the root package alone is the graph, the gallery left out) holds the graph to `deny.toml`: licenses from its allow list, permissive and MPL-2.0; no yanked crate and no RustSec vulnerability or unsound advisory at any depth, an unmaintained crate only among Ely's own dependencies, since gpui's pin brings the rest; crates.io alone as source. CI's `deny` job runs it, and its `msrv` job checks the workspace on the `rust-version` the root manifest declares.
- `sh scripts/pixels.sh BASE` captures the gallery at BASE and here on this machine and compares them (cargo keys a path crate by its place in the workspace, so the base worktree shares head's fingerprints; the script touches each tree's files before its build, or the base would reuse head's gallery) through `scripts/pixels.py` (Pillow): a pixel counts when a channel moves past its tolerance, a shot fails when its changed share passes the threshold, and the report, with each change's picture, lands in `target/pixels/report`. A commit in BASE..HEAD with a `Pixels-accepted: <why>` line lets a meant change through, but never a side with no shots or a shot more than half moving; the report keeps a picture of every failing shot, base's beside head's for a new size; a base without `scripts/pixels.py` has nothing to compare. CI's `pixels` job runs it on Linux (under `xvfb-run`), Windows and macOS and keeps the report as an artifact.
- `cargo bench -p ely-gpui-component --features test-support --bench budget`, then `python3 scripts/bench.py`, times four cases on gpui's test platform (`benches/budget.rs`): a frame of a 100,000-row virtualized `DataTable` scrolling, a typed letter and its frame in a 10,000-line `CodeEditor`, a frame of a 10,000-line `Terminal` scrolling its scrollback, and a 2 MiB Markdown read through `documents::outline`. Frames hold to 16 ms and the read to 330 ms; with `-- --baseline NAME` and `--against NAME` a bench more than 10% slower than that baseline, its interval above zero, fails. CI's `bench` job benches the base commit and this one on one runner. The test platform draws no pixels and gives each character a fixed advance, so these times are Ely's layout and scene work, not the GPU's. A bench keeps its state steady across iterations: a letter typed is taken back untimed, a scroll goes down then up. A bench times its input and the draws gpui makes for it, no forced frame, with reduced motion on; its setup holds each input to one draw of the window, after one untimed key, since gpui refreshes once when input turns from the pointer to the keyboard. A virtualized `DataTable` scrolls in the height its host gives it (`h_full`).
- `scripts/icons.sh <lucide-name>...` adds icons to `crates/ely-core/icons`. Then add a line to the `icons!` list in `crates/ely-core/src/primitives/icon/names.rs`.
- `python3 scripts/countries.py <ne_110m_admin_0_countries.geojson>` writes the bundled world; `python3 scripts/tiles.py <same file>` writes the gallery's map tiles.

## Rules

- `scripts/check.sh` fails by its exit status; a pipe into `tail` hides it.
- `python3 scripts/stability.py`, which `check.sh` runs, holds `tasks/stability.md` to its rules: every published crate has one row, unstable or stable; a stable one has the owner's signed record in `tasks/signoffs/<crate>.md`, from its `TEMPLATE.md`, naming by hash a commit that holds its `api/<crate>.txt`, and a vertical crate the address of an outside user's feedback, a host and a path, no `<...>` placeholder; `ely-gpui-component` is stable only after every other crate; a crate at 1.0 or above must be stable.
- `python3 scripts/links.py`, which `check.sh` runs, reads README.md whole, so a link split over lines counts: each relative inline link and reference definition must name a path that exists, read literally, never globbed; an `href` or `src` attribute in any form fails, since README links are Markdown.
- `python3 scripts/platforms.py`, which `check.sh` runs, holds each `Platforms:` doc line to the code. It reads each library crate's module tree as rustc does, comments, strings and doc examples aside: stacked cfgs and an enclosing module's join, a `cfg_attr` gates only when it applies `cfg`, `test` is off and features on, and a public path's `pub use` chain carries its gates, so a name that only some platforms reach must name exactly those. An item built everywhere that works only somewhere stands in `RUNTIME` with its platforms, which a cfg in its file must draw; a file that builds one stands there too or in `WRAPS` with why; any other platform cfg that limits nothing public needs its file in `SAME_EVERYWHERE` with why.
