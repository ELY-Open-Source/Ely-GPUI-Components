# AGENTS.md: ely-core

The component rules every crate follows, and core's own: gpui's ways, focus, layout, motion, theme, i18n.

## Stack

- Rust 1.98, edition 2024. A Cargo workspace (`docs/adr/0001-workspace.md`): `ely-core` (chapters 1–14, theme, motion, i18n) in `crates/ely-core`, one crate per vertical chapter in `crates/ely-<chapter>` (chapters 15–44), `ely-desktop` (the tray, the Dock badge and Omarchy, over core and devtools), `ely-gpui-component` at the root re-exporting them all, the gallery and the docs examples in `crates/ely-gallery`. `ely_core::init` loads assets and fonts and binds core keys; `ely_gpui_component::init` calls it, then binds the editor's, terminal's and documents' keys. Edition, Rust version, license, repository, shared dependencies and lints come from the workspace; each crate keeps its own version.
- gpui, gpui_platform and gpui_web from crates.io's `gpui-pre` snapshots at `=0.3.10`, Zed at 08cbb88, the pin GPUI Kit 0.8.1 holds; each keeps its crate name through `package`. These three alone pin with `=`; every other dependency takes a caret, and `Cargo.lock` holds the build. gpui takes `stacker`, which keeps deep layouts off the stack's end; gpui_platform takes `font-kit`, without which macOS draws no text, and `wayland` and `x11`, without which Linux runs headless and opens no window; they link `libxkbcommon` and, through the wgpu renderer's font-kit, `fontconfig`, so CI's Linux job installs `libxkbcommon-x11-dev` and `libfontconfig-dev`. `ely-core` takes gpui_platform only behind its `platform` feature, off by default, so a Button-only app links no gpui backend Ely chose (zbus comes with gpui's Linux window): the app turns those features on in its own gpui_platform, or `platform` does, which `ely-gpui-component` keeps on; `init` fails when the platform has no text system, naming `font-kit` (macOS) and `wayland` and `x11` (Linux), since gpui falls back to its no-op text system without them. Feature `runtime_shaders`, on in `ely-gpui-component`, turns on `platform` and gpui_platform's: machines without Xcode lack the Metal compiler.
- Icons: Lucide 1.48.0 (ISC), 307 SVGs in `crates/ely-core/icons`, each in a `static` of its own behind an `IconName` const, drawn through gpui's `svg().data`, so a binary links only the icons it names (`cargo build -p ely-core --release --features platform --example five_icons` holds five). Fonts, embedded with `include_bytes!` in `Assets`, each file a row of its table: Inter 4.1 (regular, medium, semibold, italic) and JetBrains Mono 2.304 behind `ely-core`'s `fonts` feature, on by default; an app that leaves it off registers its own and sets the theme's `font_family` and `mono_family`. IBM Plex Sans Regular (OFL) always. Plex sits unmodified, its name reserved, where gpui's svg renderer loads it: gpui_web answers `.SystemUIFont` with it, and svg text falls back to it on the web.
- Catalog data: `emojis` (Unicode emoji), ISO 639-1's 184 languages with their native names for `Combobox::languages`, a table in `forms/languages.rs` taken once from isolang 2.4 (Apache-2.0, its licence beside it), which had brought `phf` 0.11 and 15 crates, `isocountry` (ISO 3166), `iso_currency` (ISO 4217, also minor units for money), without its `iterator` feature: currencies list by ISO number, so `strum` comes from gpui alone. Second versions of a crate that Ely's own dependencies bring come only from RaTeX 0.1.15, its newest release (`tasks/optimization.md`, A4).
- Codes: `qrcode` (QR) and `barcoders` (Code 128, EAN-13), both MIT OR Apache-2.0, default features off. `rqrr` 0.11 ((MIT OR Apache-2.0) AND ISC, default features off) reads QR codes from the host's frames.
- macOS calls reach AppKit, core's (traffic lights, share picker, color sampler) and `ely-desktop`'s (tray icon, Dock badge), through `objc2` 0.6, `objc2-app-kit` and `objc2-foundation` 0.3 and `block2` 0.6 (MIT), the crates gpui links, each with only the classes Ely calls; they take a `MainThreadMarker` and panic off the main thread. The gallery's capture harness keeps `cocoa` 0.26 and `objc` 0.2, which gpui_macos still links. `ely-desktop` holds the tray: on Windows it is a `Shell_NotifyIconW` icon on a message-only window, through `windows` 0.62 (MIT OR Apache-2.0, gpui's own), its PNG read by `CreateIconFromResourceEx`; on Linux it is a StatusNotifierItem with a `com.canonical.dbusmenu` on the session bus, through `zbus` 5 (MIT, `async-io`) and `image`'s `png` decoder.
- Pictures: `image` 0.25 (MIT OR Apache-2.0), the crate gpui decodes with, default features off; it turns decoded frames and rims map tiles.

## Layout

- `crates/ely-<chapter>/src`: a vertical chapter, its `mod.rs` now `lib.rs`. The root imports core's modules and the earlier verticals it uses under their chapter names (`use ely_core::{theme, ..}`, `use ely_charts as charts`), so paths inside read `crate::theme` as before; `crate::<own module>` names its own. Its `test-support` feature forwards to core's and gpui's; tests that need keys call its own `init_for_tests`.
- `tests/`: three apps an outside crate would write, on the public API and `init_for_tests` alone, behind `test-support`: a form, folders beside a table, a workspace with a dialog and toasts. They guard what they use; E1's API snapshot guards every item.
- `src/lib.rs`: `ely-gpui-component`, which holds no chapter: it re-exports core's modules and each vertical crate under its chapter name, and its `init` binds every crate's keys. `src/shipped.rs` checks the shipped components' copy across crates.

## Rules

- Colors, control and icon sizes, text sizes, radii, shadows come from `cx.theme()`. No raw `px()` literals inside components.
- Gaps and padding use gpui's rem scale helpers (`gap_2`, `px_3`). That scale is the spacing system.
- Borders use gpui's fixed-pixel helpers (`border_1` is 1px). Hairlines do not scale. gpui paints a border no wider than half its box, so a line as thin as its box is a fill, `w_px` or `h_px` with `bg`, as the resize handles draw theirs.
- One component, one home. Duplicates point to it.
- Fail fast. No silent fallbacks. Log state changes with `log`.
- Code that needs `unsafe` lives in a crate's `platform` module, core's (`mac`: traffic lights, sharing, sampling) or `ely-desktop`'s (`mac` and `windows`: the tray and the Dock); components call its safe functions. Every unsafe block, the gallery's too, has a `// SAFETY:` line; clippy's `undocumented_unsafe_blocks` holds it.
- A handler a component needs is an argument of `new`, so leaving it out fails to compile. A state live data or the outside world can reach, a key gone from a list that changed or a failed load, logs an error naming the owner and draws a visible state, nothing chosen or an error line, and the app runs on. An assert on a caller's argument or on a fact true by construction stays; one that runtime data or input can trip is fixed. Chapters moved to this as `tasks/panics.md` ticked them. Every `expect`, `panic!` and `unreachable!` in library code is a row of `scripts/panics.tsv` with its reason; `scripts/panics.py` force-warns clippy's `expect_used`, `panic` and `unreachable` on each library, natively with every feature and for wasm32, and `disallowed_macros` and `disallowed_methods` on the same calls, which follow a local macro's body where the first three stop; each row names the hosts that report it, and each host matches its own sites exactly; it fails on a site not listed, a row this host lists that it no longer reports, a row without a reason, and a kind's count above the list at `PANICS_BASE` (default `HEAD`; CI's PR base or the commit before the push). CI runs it on Linux, Windows and macOS.
- An item public only so another Ely crate can call it carries `#[doc(hidden)]`: Ely's plumbing, out of the docs, the API snapshot and `missing_docs`. A `pub` item no path reaches is `pub(crate)`; `unreachable_pub` warns across the workspace, and the gallery, a binary, allows it.
- A component with `size(ControlSize)`, `disabled(bool)`, `selected(bool)` or an `on_change` builder implements `primitives::Sizable`, `Disableable`, `Selectable` or `Changeable` by that method, one `capable!` line at the end of its file; `Selectable` and a handler with more than one value (its `Value` a tuple) are written out. Generic code names the trait.
- A container, a component that frames an open run of its owner's content, implements `ParentElement` and has a line in `src/containers.rs`; a test there holds the list to every impl, a macro's too. A fixed place for one thing (prefix, action, footer, fallback) is a slot, not a container.
- A change an app would notice adds a line under Unreleased in `CHANGELOG.md`, naming its crates; a breaking one raises its crate's version, the minor below 1.0, and the dependents' `workspace.dependencies` entry with it.
- A file holds one responsibility; `scripts/check.sh` warns past 800 lines and never fails on size. A file under 40 lines is a module entry or a type of its own. Comments are one short line, and rare. Every public item carries rustdoc, `#![deny(missing_docs)]` in each library crate, and each component's doc holds an example that compiles and runs (`cargo test --doc`); `check.sh` holds plain `//` comments to one line and lets `///` and `//!` run on.
- A repeating animation (spinner, breath, sweep) holds still under reduced motion instead of shortening, or it would spin at 1 ms a turn. An effect set off by a change (flash, shake, a bar that fades at rest) reads elapsed time through `motion::since_change` rather than restarting an animation id, so what it holds keeps its state: an animation's id passes to every descendant, and a new one rebuilds their focus, drags and hover.
- `motion::duration()` honors reduced motion. Springs overshoot. gpui hands an easing's value to the whole animator unclamped, so `motion::spring` goes inside the animator, on only what may overshoot (`forms::Switch` springs its thumb's travel, not its colors).
- `svg()` paints only with its own `text_color`. `Icon` always sets one.
- Buttons stay out of focus on click (`prevent_default` on mouse down). Tab still reaches them.
- The focus ring is a 1px focus-colored border (`FocusRing`). gpui paints shadows under the element, so a shadow ring floods transparent elements. Focusable elements keep a 1px border, transparent at rest.
- `ely_gpui_component::init` binds Tab and Shift-Tab to `FocusNext` and `FocusPrev` under `ElyFocus`, the key context every `FocusScope` sets. gpui ranks a binding with no context at the deepest level, so a host's Tab in a deeper context, GPUI Kit's code editor among them, lost or won by which `init` ran last; under a context, the deeper one wins. Wrap the root in `FocusScope` with `.root()` and focus its handle. A root scope takes focus when the focused element leaves the tree, as a toast's or an alert's button does.
- `hover()` needs an element id.
- gpui takes hover at layout only on an element with an id, from a state its mouse moves keep, so `.id(..).hover(..)` recolors text. Without an id, `hover` applies at paint, after the text took its color, and a mouse move alone redraws nothing. After a key press paint drops the hover and layout keeps it until the mouse moves, so a hover that sets text and background shows only the text. What shows on hover rests `invisible()` and turns `visible()` through `group_hover` (`chat::ConversationItem`, `messaging::ChatMessage`).
- Whatever draws over the page goes through `primitives::raise`: at the top it defers; inside something raised it lays out on its own and draws last there, so a list opened in a dialog lies over the dialog. gpui takes a deferred draw inside another but paints them all by priority alone, so a tooltip (0) deferred inside a fullscreen dialog (1) would draw under it. A raise takes its owner's id and draws under it, so its keyed state and focus hold while other raises come and go. `scripts/check.sh` refuses gpui's `deferred` anywhere else.
- gpui hides hover after a key press until the mouse moves. A hover that holds or shows something (the toast stack, a carousel, tooltips, hover cards, charts, scroll activity) sets `HoverListenerMode::InputModalityIndependent`, so typing under a resting pointer keeps it. A hover preview the keyboard also moves keeps the default on its items; the box that clears it on leave listens independently, so a real exit still reports, and ignores a leave that follows a key through `last_input_was_keyboard` (`forms::Calendar`).
- `occlude()` blocks the pointer for everything painted before it, its own ancestors too. Put it on the outermost box that should stop the pointer, as the toast stack does, or the ancestors' hover never fires.
- A control inside a `drag_region` occludes it. On Windows gpui answers the system's hit test with the caption wherever a `Drag` hitbox lies under the pointer unoccluded, and Windows then keeps the press: no click reaches the control. `block_mouse_except_scroll` is not enough, since that answer reads every hitbox under the pointer. Window buttons occlude, which lets them answer as close, maximize and minimize, and so do a title bar's slots; a column header's item row occludes, staying the scroll container, and its title is a drag region of its own; the mini window drags by its title alone, so its buttons sit outside the region and its hover still shows the bar.
- A drag that pans, turns or slides goes through gpui's drag, whose moves reach the owner in or out of its box; `on_mouse_move` stops at the box's edge. gpui sends a drag's moves to every listener of its type, so each payload carries its owner's `EntityId` and handlers check it.
- A box that keeps a cursor over its items rings the item the cursor is on, not the box, as SelectableList marks its row (`interaction::SelectionArea`).
- Boxes that scroll together go through `interaction::ScrollSync`: the pane a wheel turned leads, and a canvas laid before the panes copies its place in prepaint, before they draw, so no frame shows them apart.
- A component that takes a starting value from its owner keeps it in `layout::seeded`: a new value from the owner replaces local drags. A field that reports its words as they change keeps what it sent, so the owner's echo leaves the caret alone (`mail::SignatureEditor`). A cursor inside a seeded view stays while it lies in what is shown, so the owner's echo of a turn leaves it (`calendar::CalendarMonthView`, `YearView`). A number field keys the owner's value as shown: a new one waits while the field is focused and lands before the blur commits, and an echo of its own commit is no new value (`forms::NumberInput`). A ranged number field holds room for its widest bound through `Input::least`, since a text field has no width of its own.
- An overlay takes focus with `primitives::take_focus` and returns it with `give_back` on every close path. While open, it takes focus back whenever the focused element leaves the tree (gpui's `on_focus_lost`).
- A state change made outside render calls `cx.notify()`, or nothing redraws. A notify made while drawing, as in a canvas's prepaint, marks the view but schedules no frame (gpui's `invalidate_view`), so it also calls `window.request_animation_frame()`.
- Every text field is a `forms::TextInput` entity. Its keys live under the `ElyInput` context, bound in `init`. Wrappers take Up, Down, Enter and Backspace first with `capture_action`.
- `TextInput::bounds_for` reads the last layout. Text changed this frame clamps to the laid-out end until the next paint.
- gpui's `test-support` and `leak-detection` stay behind this crate's `test-support` feature and are never on for the gallery: one records every `debug_selector`'s bounds each frame, the other tracks every entity handle, so a test that leaks one fails (`tests::a_leaked_entity_fails_its_test`).
- A tracked `FocusHandle` is a Tab stop only when built with `.tab_stop(true)`. `tab_index` on the div reaches only handles gpui makes itself. `primitives::tab_stop` keeps one per id.
- Floating lists go below their anchor, or above when only above has room (`forms::options::float`). gpui's own switch keeps the anchor point, so a flipped list would cover its trigger. An option list is at least its trigger's width and at most the window's less `window_margin` each side, so gpui can snap it inside and its rows end in an ellipsis; wider, gpui pins it left and the rest runs off.
- A trigger that opens a list goes through `forms::select::listing`: toggle, keys, blur and popup live there, for Select, TabOverflowMenu and Breadcrumb alike. A field that suggests as you type floats its rows through `forms::select::Picker` and `forms::options::Popup`, as Combobox and TagInput do.
- A palette goes through `navigation::palette::Palette`: query field, grouped rows, cursor, keys and focus live there. CommandPalette, QuickOpen, QuickSwitcher, SearchPalette and QuickLauncher only build rows.
- A menu goes through `menus::menu`: rows, submenus, keys, focus and presses outside live there, for DropdownMenu, OverflowMenu, SplitButton, ContextMenu, SearchableMenu and MenuBar. A press on the host's own box is the host's to handle, so a trigger toggles and a right click moves a context menu without a close and reopen in one event. A row of icon buttons (`Menu::buttons`) is one entry: Up and Down reach it, Left and Right cross it, a reader presses a button through Click and hears the marked one, and a mark holds its item by label, so a row that changes under it runs nothing unasked. Panels occlude what lies under them. A submenu that does not fit on the right opens on the left of its row, sliding in from that side. A row's submenu opens once the pointer rests on it 150 ms; while a submenu is open, a row crossed inside the triangle from the last pointer place to the submenu's near corners waits 300 ms and switches only if the pointer still rests there (`menus::aim`); a row outside it marks at once. Keys and presses open at once.
- gpui focuses the nearest focusable ancestor on mouse down, and apps wrap everything in a `FocusScope`. A press that must leave focus alone calls `prevent_default`, as buttons and context regions do.
- gpui runs the click of every pressed element under the pointer, a row's with its button's. A pressable row that holds buttons stops their press at their box on mouse down (`files::transfer`), as `overlays::media_button` stops its own.
- gpui draws a window's first frame inside `open_window`. State the first frame reads, such as `cx.set_menus`, is set before it opens.
- gpui clicks a focused element when Enter or Space is released, and only if the press reached it and focus stayed there. An overlay that hands focus back picks on release too. An edit in place that hands focus back keeps its text on Enter's release (`forms::InlineEdit`). The press itself bubbles, so a container that takes Space leaves a focused button its own: `overlays::media_button` stops it, and a button in a `SelectableList` row stops Space and Enter at its box (`mail::MailItem`'s star, `messaging::PinnedMessages`' Unpin). A key context that binds a key its children use acts only while its own handle is focused and propagates otherwise, or a focused child never arms (`editor::CodeEditor`'s Newline).
- A focus handle a component hands back lives across all its modes: take it with `tab_stop` before any early return, or keyed state drops it while the other mode draws and the handed-back focus lands nowhere. A thread's message keeps one handle folded and open, a Tab stop only while folded (`mail::MailThreadView`).
- A button whose words and action change with a mode keeps one handle through `Button::focus_handle`, and the component moves focus to it or back to its field as the mode turns (`project::TimeTracker`).
- A button that waits on the owner shows it with `loading`, which takes no press and stays a Tab stop, so focus holds through the wait; `disabled` is for what is not ready, and a disabled button is no stop (`onboarding::ContactSupport`).
- A control names its role, label and state on the element that takes focus, for gpui's AccessKit tree (a slider's thumb, a select's trigger). gpui sets no disabled flag, so a disabled control says `state.unavailable` in its description. A thumb bounded by another reports the bounds it can reach. The test platform builds no tree, so `gallery --audit` proves it on Windows: a UI Automation client in another process wakes gpui's tree, it steps every page's Tab stops through gpui's `focus_next`, so neither a focus trap nor an editor that keeps Tab hides the stops past it, and a stop with no node, or a node with no name, fails it. A grid, list or menu whose focus stays on its box names the cursor's item as its active descendant, and the audit reads that. gpui 0.3.9 honors that claim only inside the focused element, so a list a typed filter drives (`SearchableMenu`, the palettes, `Combobox`, `TagInput`, `mail::LabelPicker`), whose focus stays in its field, announces the field, not the highlighted row: a gpui limit, open until gpui takes an active descendant outside the focused element. A name comes from what the component draws: a label, a title, a date; where it draws no words, a catalog key; a field an owner passes in is the owner's to name.
- A help mark, ?, is `primitives::HelpTooltip`; FormLabel's help shows it.
- A `FormField` names the field it frames: its label, and its error or else its description, are in scope while its control lays out (`forms::naming`), and `Input` hands them to its `TextInput`, a name after the owner's own label and before the placeholder. gpui renders a child component while its parent lays out, and a cached view in prepaint, so the scope holds both phases, as a context would; a cached view renders again only when it notifies, so a changed label reaches it then.
- An overlay that traps focus names its scope (`FocusScope::node`): the scope is what takes focus, and gpui announces a focused element with no node as the whole window. A `Dialog` without `focus_first` moves focus to its first control a frame after it opens, Cancel in a confirm, as macOS's alerts do, tried once per opening, so a dialog with no stop settles on its scope. An untitled `ActionSheet` and a captionless lightbox picture name their scope from the catalog (`sheet.name`, `lightbox.name`). VoiceOver does not follow focus gpui moves without a key press, and gpui 0.3.10 marks no node modal: both stay open upstream (`tasks/voiceover.md`).
- A panel that opens from something other than a button goes through `overlays::Popover::with_opener`, which hands the opener its toggle; focus, placement and every way out stay in the popover (`calendar::EventPopover`'s chip). Its content gets a close that hands focus back: a press that ends the panel's work closes it before the owner acts, or a panel whose host leaves the tree strands focus (`onboarding::Hotspot`'s Got it, EventPopover's Edit and Delete).
- A flow in steps goes through `navigation::Wizard`: Back, Next, Finish and the step's motion live there. Next and Finish share one focus handle, and focus moves to it when Back reaches the first step or a finished step is picked. `onboarding::OnboardingWizard` leaves out its numbered steps (`headless`) and shows a count over a bar in as many parts.
- A dialog goes through `overlays::Dialog`: scrim, focus trap, Escape and focus return live there. Its close runs on every way out, so a dialog with two answers marks the chosen one before it closes (`messaging::IncomingCallDialog`). AlertDialog, ConfirmDialog and PromptDialog build on it; a fullscreen dialog fills the window below its title bar. A dialog's card fits the window, a title bar's height clear at each end; its body scrolls and its actions stay.
- Controls on a dark layer over pictures are `overlays::media_button`, light icons that dim when they have nowhere to go, for the lightbox and a video player's bar alike.
- A component's letter keys step aside while Command or Control is held, so the app's shortcuts reach the app (`media::ImageAnnotator`, `VideoPlayer`, `VideoThumbnailStrip`).
- `primitives::Severity` names info, success, warning and danger with their colors and icons, for alerts and feedback alike.
- Rows that move are keyed. `motion::Flip` places them absolutely from last frame's heights, so no frame shows a row at its new place before it glides there, and drives the glide from elapsed time: an animation id that changes per move would rebuild the row's keyed state. `Reorder` holds a row by key, drags with an empty ghost and moves the held row itself.
- A marker that slides between items (segment thumb, tab line) measures them with `motion::slide` and eases with `glide`.
- A picker hands focus to its popup on open and back to its trigger on pick or Escape; it closes once focus leaves both (`forms::date::picker`). `messaging::StatusSetter`'s emoji field reuses it.
- Motion for a value change keys its animation on `motion::changes`, so it replays per change and stays still on first paint. Key only the part that moves: a keyed ancestor gives every descendant a new id, and focused buttons lose focus.
- A spotlight or tour takes its target's box from `primitives::Measure`; the lit box glides between targets.
- Thumbs stay inside their component's box: the track is padded by half a thumb (`Slider`, `ColorPicker`, `GradientEditor`, `media::ImageCropper`).
- gpui's `Hsla::opacity` scales alpha; `alpha` sets it.
- A rounded box does not clip its children. Each layer inside takes the radius itself; `checker` takes one.
- A window keeps one `feedback::Toaster` and renders one `ToastViewport`; anything holding the entity pushes to it. Messages share `primitives::Severity`.
- Drop rules live in `forms::files::dropped`. `taken` adds file kinds by extension, for drops and the dialog alike (`DropZone::kinds`).
- What a dropped file leads to is drawn by a function of what was read (`settings::importer::read_row`). gpui's test platform builds `ExternalPaths` with paths and answers a file dialog through `simulate_path_prompt_response`.
- A stroke drawn with the pointer goes through `forms::pen`: a press starts it, a drag extends it, and the lift hands it over, in or out of the pad (`SignaturePad`, `generative::InpaintCanvas`, `calendar::TimeGrid`'s drag on empty time).
- gpui runs key bindings before key listeners. A container takes a child's bound key through the action with `capture_action`, as `Form` takes `Submit`.
- `ScrollHandle::scroll_to_item` runs in the container's prepaint against last frame's bounds and overflow, so a call before a list's first frame does nothing. Call it from a child's prepaint once the handle has bounds, then request one frame (`navigation::editor_tabs`). A floating list reveals its cursor, and a strip its focused item, through `forms::options::reveal` and `revealer`. A focused Tab stop deeper in a scroll box sets the box's offset whole from its own painted bounds in prepaint, once per focus, through `layout::bring_into_view` along the box's axis; the canvas measures the stop with its ring (`messaging::GifPicker`). `layout::reveal_when_focused` is that canvas; it lies over a box that holds the stop's ring (`buttons::SegmentedControl`, `project::KanbanBoard`). Never poll layout with `request_animation_frame`.
- gpui animations run on the wall clock, except `Animation::repeat_synced` loops, which read the executor's clock; timers run on the executor's clock, which tests advance by hand. A test that needs an animation settled turns on the theme's reduced motion. Clocks read `background_executor().now()` and wake only their own view.
- Machine-read marks, QR codes and barcodes, paint `ink` on `paper`: dark on light in both themes, so cameras read them.
- A layer over pressable content that must still pass scrolls to its ancestors uses `block_mouse_except_scroll`; `occlude` hides them from scrolls too.
- Trackpad momentum arrives as `TouchPhase::Moved` after `Ended`, so a gesture acts only between `Started` and `Ended` (`lists::SwipeableListItem`).
- A chevron that opens and closes is `primitives::Disclosure`.
- `uniform_list` does not stretch its rows; each row sets `w_full`, or `min_w_full` when the same row also sits in a flex column, where it stretches (`tables::DataTable`). gpui's `list` lays rows at their content's width too; `chat::MessageList` boxes each row at the list's width.
- Chapters import only earlier chapters, so a select of tree nodes lives in `lists` (`TreeSelect`) and reaches `forms::listing`.
- Reduced motion shortens animations to 1ms on the wall clock. Tests sleep past it between refreshes to see where one ends.
- Tests never depend on the host. The svg font database (`documents::svg_options`) reads no system fonts under test, only the OFL subsets in `crates/ely-documents/src/fixtures` and bundled IBM Plex; gpui's `SvgRenderer` loads host fonts, so a test outlines text before gpui draws it. Mermaid measures labels with host fonts, so diagram tests assert no geometry. A test whose premise the host breaks, a mode 600 folder under root, skips and says so. gpui's test scheduler runs tests off the main thread, where AppKit deadlocks on macOS 27, so a window opened under it (`App::is_test`) asks AppKit for no traffic light origin. A test that compares two sizes' times reads the thread's CPU time through `documents::clock::spent` (rustix's `ThreadCPUTime`), since the shared Mac runs other suites at once; Windows, with no safe thread clock, reads the wall clock.
- The test platform runs next-frame callbacks only when a test calls `Window::simulate_next_frame`. Its text metrics are simplified: each character takes a fixed advance, unless the test builds its context with `TestAppContext::build_with_text_system`. Tests refresh the window in place of the display link, and click where layout does not hang on text, such as padding and slots.
- An absolute element with no insets sits where it would flow: after the content in a block, inside the padding in a flex box. A canvas that measures its parent pins itself with `.top_0().left_0()`.
- Keyed state lives while its element renders in consecutive frames. An overlay rendered only while open starts fresh each time.
